# Разработка Telegram-ботов

Используй этот скил для выбора возможностей Telegram, реализации и проверки бота. Он не привязан к языку, фреймворку или хостингу. Основной источник — [Telegram Bot Features](https://core.telegram.org/bots/features); точные поля, методы и ограничения всегда сверяй с [Bot API](https://core.telegram.org/bots/api) и, для Mini Apps, с [отдельным руководством](https://core.telegram.org/bots/webapps). Снимок справочников проверен 27 октября 2026 года по Bot API 10.3. Перед реализацией функции открой актуальную документацию: Bot API и клиентская поддержка меняются, а SDK может отставать.

## Как работать

1. Определи целевой сценарий и поверхность: личный чат, группа/тема, канал, директ канала, Business, гостевой вызов, inline, Mini App или веб-сайт. Зафиксируй, кто инициирует действие и какие данные бот вправе видеть. Для выбора см. [карту возможностей](references/feature-map.md).
2. Для нужной поверхности прочти только соответствующие справочники ниже. Найди конкретные типы `Update`, методы, права и переключатели BotFather в официальной документации. Отличай наличие функции в Bot API от её доступности для конкретного бота, клиента и установленного SDK.
3. Для существующего бота сначала проверь исходный репозиторий, текущую конфигурацию и способ получения обновлений; при работе с развёрнутым сервисом сравни Git, Compose/systemd и реально работающую версию. Следуй локальному `AGENTS.md`. Создание нового бота, смена токена, webhook или запуск poller не следуют автоматически из проектирования.
4. Реализуй обработку входящего события, проверку полномочий и явный ответ/завершение протокола. Выбери состояние и идемпотентность по реальным побочным эффектам: доставка может повториться, callbacks и платежи нельзя считать однократными.
5. Проверь сценарий в отдельном тестовом боте или тестовой среде, затем поведение в нужном типе чата и клиенте. Для запуска в продакшене проверь ограничения и наблюдаемость. Не считай изменение Git автоматическим обновлением запущенного бота.
