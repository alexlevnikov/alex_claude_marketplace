# Настройка, проверка и эксплуатация

Официально: [BotFather and Bot Management](https://core.telegram.org/bots/features#botfather-creating-and-managing-bots), [Testing](https://core.telegram.org/bots/features#testing-your-bot), [Status Alerts](https://core.telegram.org/bots/features#status-alerts), [Bot API](https://core.telegram.org/bots/api), [FAQ](https://core.telegram.org/bots/faq).

## Настройки, которые влияют на код

| Настройка | Что сверить |
| --- | --- |
| Токен и владелец | Какой bot ID отвечает `getMe`; где лежит секрет; как отозвать токен при утечке. Токен даёт полный контроль над ботом. |
| Команды, профиль, меню, языки | Реальный список команд, scope, публичное описание, аватар/видео, menu button и локализация. |
| Group privacy и join groups | Получает ли бот нужные сообщения группы; требуются ли admin rights; применились ли изменения после повторного добавления. |
| Inline, Guest, Bot-to-Bot, Managed, private topics, Mini App | Отдельные переключатели/настройки в BotFather; документируй только те, что нужны продукту, и проверяй их на целевом боте. |
| Webhook/polling | Один выбранный транспорт, `getWebhookInfo`/текущий poller, `allowed_updates`, секрет и очередь. |
| Права в чате | `getChatMember`/админские права и Business rights по конкретному действию. |

## Среды и выпуск

- Для обычной разработки используй отдельный бот с отдельным токеном. В [выделенной тестовой среде](https://core.telegram.org/bots/features#dedicated-test-environment) нужны отдельный пользователь и отдельный бот; адрес API имеет `/test/` перед именем метода. `file_id` продукционного бота там не переносится. Лимиты тестовой среды не обещают быть мягче.
- Перед выпуском проверь [Recent changes](https://core.telegram.org/bots/api#recent-changes), текущую версию SDK и фактическую поддержку нужных полей. Для нового метода допустим небольшой прямой вызов Bot API поверх существующей библиотеки, если он покрыт проверкой ответа и не ломает обработку обновлений.
- Зафиксируй способ развёртывания и отката, затем проверь активную версию процесса/образа после изменения. На VPS следуй локальному реестру проектов и сверяй Compose/systemd с checkout; не запускай второй poller для того же токена. Изменение исходников само по себе не обновляет контейнер.
- Если нужен [локальный Bot API](https://core.telegram.org/bots/api#using-a-local-bot-api-server), проверь его документированные отличия по файлам/webhook и процедуру `logOut` при переключении. Это отдельный сервис, а не обязательная часть обычного бота.

## Наблюдаемость

Смотри задержку доставки update, глубину очереди, ошибки Bot API и `retry_after`, долю отвеченных callback/inline queries, успешность платежей, время ответа и ошибки Mini App auth. Логи должны помогать связать `update_id`/заказ с попыткой обработки без токена, содержимого приватного сообщения или сырого `initData`. [BotFather status alerts](https://core.telegram.org/bots/features#status-alerts) сигнализируют о падении частоты ответов; они дополняют собственные метрики.

## Приёмка по выбранной функции

Проверяй не список всех функций, а реальный маршрут пользователя: новый и повторный `/start`; неверные права; callback с повтором; сообщение нужного типа и языка; перезапуск в середине обработки; 429/5xx; отказавший клиентский метод; при оплате — повтор, отмена и возврат. Для групп отдельно проверь Privacy Mode и роль бота, для Mini App — подпись и срок `initData`, для Business — текущие rights.
