# Платежи и монетизация

Перед реализацией классифицируй товар. Для цифровых товаров/услуг внутри Telegram используй [Telegram Stars (`XTR`)](https://core.telegram.org/bots/payments-stars); для физических товаров/услуг — [платёжного провайдера](https://core.telegram.org/bots/payments). Не переноси тестовые реквизиты и правила одного режима в другой. Также проверь действующие [Bot Developer Terms](https://telegram.org/tos/bot-developers) и требования магазинов приложений для выбранного продукта.

## Общий протокол заказа

1. Создай внутренний заказ с неизменяемым ID, ценой, валютой, пользователем и сроком действия. В `payload` инвойса передавай opaque ID, не доверяй сумме из клиентского интерфейса.
2. Отправь [sendInvoice](https://core.telegram.org/bots/api#sendinvoice) или invoice link с параметрами нужного режима. Для цифровой продажи `currency=XTR`; provider token может быть пустым. Для физической продажи нужен подключённый провайдер и, при необходимости, варианты доставки/контактные данные.
3. Обработай `shipping_query`, если он используется, и `pre_checkout_query`. Перед [answerPreCheckoutQuery](https://core.telegram.org/bots/api#answerprecheckoutquery) перепроверь заказ, цену, валюту, доступность и право пользователя. Ответь в требуемый Telegram срок; долгое подтверждение вынеси в подготовку до checkout.
4. Выдавай товар только после `successful_payment`, сверив заказ и сумму. Сохрани `telegram_payment_charge_id`/данные провайдера, необходимые для аудита и возврата. Сделай выдачу идемпотентной по платёжному идентификатору; повторный update не создаёт вторую подписку или вторую доставку.
5. Реализуй поддержку и возвраты для выбранного режима: [refundStarPayment](https://core.telegram.org/bots/api#refundstarpayment) для Stars, провайдерский процесс для физических платежей. Сверь статусы и доступный остаток с текущим Bot API.

## Дополнительные модели

- [Подписки](https://core.telegram.org/bots/payments-stars) и `botSubscriptionUpdated`: различай факт успешной оплаты, срок доступа, продление, отмену и возврат. Доступ вычисляй из сохранённого состояния, а не из факта нажатия Pay.
- [Платные медиа](https://core.telegram.org/bots/api#sendpaidmedia) открываются после оплаты; в канале и Business-потоке нужны соответствующие права.
- Подарки, Stars-баланс, вывод наград и платная рассылка имеют отдельные методы и условия в [Bot API — Payments](https://core.telegram.org/bots/api#payments). Включай их только при конкретном требовании; сверяй версии API и юрисдикцию.
- Revenue share Telegram Ads — механизм платформы, а не альтернатива платежам за конкретный заказ; см. [Monetization](https://core.telegram.org/bots/features#monetization).

Тестируй покупку, отмену, двойной callback/update, истёкший заказ, неверную сумму, ошибку выдачи и возврат в предусмотренной Telegram тестовой среде или режиме провайдера. Не запускай реальную оплату ради простой проверки обработчика.
